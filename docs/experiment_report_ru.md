# Отчёт по экспериментам - Domain-Aware Prompt Engineering для научного QA

Отчёт по реализации магистерской диссертации. Документ сводит воедино **как
прогонялась каждая фаза и гипотеза, на каких данных, с какими параметрами,
какие результаты получены и как их понимать**. Написан так, чтобы материал
можно было напрямую перенести в Главу 4 (Методология) и Главу 5 (Результаты).

Статус: все фазы экспериментов (D, E, F, G, H, I) выполнены и проверены
автоматическим аудитом целостности. Единственное опциональное, что не
запускалось, - проприетарный калибровочный судья (judge_c); его отсутствие не
влияет ни на один основной результат.

## 1. Общая постановка эксперимента

Все модели локально под vLLM, 4-бит квантизация (AWQ; gemma - awq_marlin),

### 1.2 Данные

- **Track A - SciKnowEval** (основной). Сэмплированный сплит
  `data/sciknoweval/main_test_sampled.json` = **3003 вопроса**,
  стратифицированный (`--n-floor 3` на страту, поэтому 3003, а не 3000).
  Домены: Physics, Materials, Biology, Chemistry, Computer Science. Типы
  вопросов смешанные (~68% MCQ на 4 варианта, плюс true/false, fill-in,

  smoke-тестов.
- **Track B - QASPER** (приложение). Сэмплированный сплит
  `data/qasper/sample.json` = **600 вопросов**, стратифицированный, seed 42,
  развёрнут из 5049 аннотаций. ~10% - **unanswerable** by design (пустой gold,
  `question_type = "unanswerable"`). Корпус уровня статей: 90 608 FAISS-векторов.

### 1.4 Стратегии промптинга (4)

- **DA (Direct Answer)** - краткий ответ + короткое обоснование.
- **RAS (Rubric-Aware Structured)** - ответ + ключевые рассуждения +
  неопределённость + уверенность.
- **CTL (CoT-lite)** - пошаговое внутреннее рассуждение, на выход финальный
  ответ + рационал.
- **SC (Self-Consistency)** - 5 сэмплов при T=0.7, голосование большинством.

### 1.5 Ретриверы (3)

BM25 (Elasticsearch), dense (FAISS + BGE-эмбеддинги), hybrid (RRF из BM25+dense,
затем реранкер BGE).

### 1.6 Оборудование

Целевое по дизайну: RTX 4060 8GB / Ryzen 7 5700X / 16GB RAM / Win11 + WSL2.
Продакшн-прогоны (включая панель судей) выполнены на узле NVIDIA A100 80GB
(`innodatahub`, JupyterLab).

## 2. Методология и результаты по фазам

### Фаза D - Closed-book инференс

**Как.** Каждая из 24 ячеек прогоняет все 3003 вопроса Track A через одну модель
с одной стратегией без контекста. Greedy-декодинг (SC = 5 сэмплов + голосование).
Ответы парсятся в нормализованную форму (`parsed.answer_normalized`, для SC -
`sc_result.final_answer_normalized`) и оцениваются Exact Match с нормализацией по
типу вопроса (MCQ -> буква, T/F -> yes/no, open-ended -> нормализованный текст).
Выход: `outputs/closed_book_main_test/<model>/<strategy>.jsonl`.

**Результаты (средний Exact Match по 4 стратегиям, по моделям):**

| Модель | Параметры (B) | Closed-book EM |
|---|---|---|
| gemma-2-9b | 9.0 | 0.571 |
| qwen2.5-7b | 7.6 | 0.569 |
| mistral-nemo-12b | 12.0 | 0.568 |
| sciphi-mistral-7b | 7.0 | 0.524 |
| llama-3.2-3b | 3.2 | 0.523 |
| deepseek-r1-qwen-7b | 7.0 | 0.502 |

Лучшая стратегия в целом: **Self-Consistency (SC)**. Parse success >= 95% в
каждой ячейке.

**Понимание.** На одном лишь параметрическом знании лидируют крупные/хорошо
инструктированные универсалы (gemma, qwen, nemo); размер модели умеренно
коррелирует с closed-book точностью (Pearson r = 0.62, см. H1). SC - самая
надёжная стратегия, что согласуется с литературой по self-consistency.

### Фаза E - Корпус, индексы, ретривал (инфраструктура)

**Как.** Корпус Track A нарезан на окна 256/64 токена (tiktoken). BM25-индекс в
Elasticsearch (k1=1.2, b=0.75); dense FAISS-индекс из BGE-base-en-v1.5; hybrid =
RRF (k=60) из BM25+dense, затем реранкер BGE-reranker-v2-m3. Track B (QASPER) -
свой корпус уровня статей и индексы (90 608 векторов). Фаза - фундамент F и G;
её корректность косвенно валидируется проверками провенанса в аудите (раздел 4).

### Фаза F - Основная RAG-матрица

**Как.** Как Фаза D, но к промпту добавляются топ-10 ретривнутых пассажей, часть
которых заменена шумом согласно уровню. Позиции шума используют стабильный
per-question seed (`seed + hash(qid)`), сборка воспроизводима. Каждая запись
хранит полный провенанс: `passages_used[]` (с `chunk_id` и `noise_type` из
{real, irrelevant, contradictory, injection}), `retriever`, `noise_level`,
`strategy`, `model`. Выход:
`outputs/rag_main/<model>/<retriever>_noise<lvl>_<strategy>.jsonl`.

**Результаты (средний Exact Match по всем RAG-ячейкам, по моделям, против
closed-book):**

| Модель | Closed-book | RAG | Delta (RAG - CB) |
|---|---|---|---|
| gemma-2-9b | 0.571 | 0.549 | -0.021 |
| mistral-nemo-12b | 0.568 | 0.540 | -0.027 |
| qwen2.5-7b | 0.569 | 0.503 | -0.066 |
| deepseek-r1-qwen-7b | 0.502 | 0.486 | -0.016 |
| llama-3.2-3b | 0.523 | 0.479 | -0.045 |
| sciphi-mistral-7b | 0.524 | 0.286 | **-0.238** |

**Понимание.** RAG-точность **ниже** closed-book у каждой модели на этом
MCQ-ориентированном бенчмарке, и дефицит **не** растёт с размером модели
(corr(size, RAG) = 0.35 < corr(size, closed-book) = 0.62). На закрытых MCQ
ретривнутые пассажи работают как дистракторы, доминирует параметрическое знание;
добавление шума это не меняет для здоровых моделей (см. H2). SciPhi - выброс
(-0.238): RAG **format collapse** (ограничение L3). Этот headline-результат
мотивирует измерять устойчивость к шуму open-ended judge-метриками, а не только
MCQ-точностью.

**Разложение просадки RAG (EM vs EM_parsed).** Чтобы исключить, что падение -
просто артефакт парсинга (длинные RAG-ответы хуже парсятся), сравниваем сырой
Exact Match (непарсенное = неверно) с EM_parsed (точность только по успешно
распарсенным ответам):

| Модель | delta EM (всё) | delta EM_parsed (только чистые) |
|---|---|---|
| gemma-2-9b | -0.021 | -0.021 |
| mistral-nemo-12b | -0.027 | -0.019 |
| deepseek-r1-qwen-7b | -0.016 | -0.028 |
| llama-3.2-3b | -0.045 | -0.025 |
| qwen2.5-7b | -0.066 | -0.047 |
| sciphi-mistral-7b | -0.238 | -0.143 |

Просадка RAG **сохраняется на чистых ответах у каждой модели** (-0.019…-0.047;
SciPhi -0.143), то есть это **настоящий эффект дистракции знания**, а не артефакт
парсинга. Разница между столбцами - вторичный **штраф за формат**: RAG-промпты
провоцируют более длинные, чаще обрезанные/непарсящиеся ответы (citation
runaway, L4), которые сырой EM считает ошибкой (заметно у llama, qwen, sciphi;
почти нет у gemma). Эффект мал и согласован у здоровых моделей - подпись мягкой
дистракции, а не дефекта. SciPhi деградирует даже на чистых ответах (-0.143),
т.е. ломается само рассуждение, а не только формат (L3).

**Почему RAG отвлекает: доменный mismatch ретривала.** Прокси доменной
согласованности (`scripts/extra_checks.py`) при noise 0 меряет долю извлечённых
(не-шумовых) пассажей, чей домен совпадает с доменом вопроса: Biology 84.8%,
Chemistry 54.8%, **Physics 37.6%, Materials 8.3%**. Где доля низкая - ретривал
возвращает пассажи из чужой области, работающие как дистракторы; это
механистическое объяснение результата «closed-book > RAG», сильнее всего там,
где ретривал наименее тематичен (Materials, Physics). У вопросов по Computer
Science вообще нет соответствующего домена в корпусе (корпус покрывает
biology/chemistry/physics/materials/earth-science), поэтому CS-ретривал заведомо
off-domain - что согласуется с тем, что CS - домен с минимальной рубрикой у
панели судей (2.14). Это переосмысляет H1: RAG вредит не потому, что «ретривал
бесполезен», а потому, что релевантность ретривала неравномерна по научным
доменам на этом корпусе.

### Фаза G - QASPER (Track B, приложение)

**Как.** 48 ячеек (только hybrid, шум {0%, 60%}) на 600 вопросах QASPER, оценка и
автометриками, и панелью судей. Ответы QASPER open-ended
(extractive/abstractive/yes-no) плюс ~10% unanswerable.

**Результаты.** Exact Match не информативен для open-ended QASPER (EM ~ 0.07);
информативный сигнал Track B - **judge-рубрика** (48 ячеек QASPER входят в панель
судей, Фаза H). 60/600 (10%) вопросов unanswerable by design (пустой gold) -
проверяют воздержание, а не точность ретривала. Агрегация 1920 QASPER
judge-записей (`scripts/qasper_track_b_table.py`):

| Группа | n | средняя рубрика | faithfulness | coverage |
|---|---|---|---|---|
| overall | 1920 | 2.14 | 0.051 | 0.313 |
| strategy = RAS | 480 | **2.23** | 0.046 | 0.321 |
| strategy = SC | 480 | 2.15 | 0.048 | 0.308 |
| strategy = CTL | 480 | 2.10 | 0.064 | 0.312 |
| strategy = DA | 480 | 2.09 | 0.044 | 0.311 |
| noise = 0% | 960 | **2.23** | 0.041 | 0.305 |
| noise = 60% | 960 | **2.05** | 0.060 | 0.321 |

**Понимание.** Track B - проверка переноса на второй формат научного QA (статьи
по NLP). Два ключевых вывода. (1) В отличие от MCQ-точности Track A (где шум не
влиял), на open-ended QASPER по рубрике **шум ухудшает качество** (2.23 -> 2.05
при шуме 0% -> 60%) - прямое свидетельство, что open-ended judge-оценка ловит
чувствительность к шуму, которую exact-match MCQ маскирует. (2) RAS
(структурированный промпт с учётом рубрики) - лучшая стратегия на QASPER, впереди
SC: структурирование помогает на свободных научных ответах сильнее, чем на MCQ.
Абсолютные рубрики низкие (~2.1 из 5) - отражает сложность QASPER и строгий порог
NLI faithfulness.

### Фаза H - Панель LLM-судей

**Как.** Два независимых open-weight судьи, отличных от всех семейств экзаменуемых,
оценивают стратифицированный субсет **N=20 вопросов на ячейку** по всем 216
ячейкам (24 closed-book + 144 RAG + 48 QASPER) = **4320 оценённых ответов на
судью**. Одни и те же 20 вопросов оцениваются в каждой ячейке - полное
пересечение judge_a/judge_b для надёжности. Каждый ответ получает:

- **Рубрику 0-5** (шестибалльное качество).
- **Faithfulness** - ответ декомпозируется на атомарные утверждения; каждое
  проверяется NLI (DeBERTa-v3-large) на entailment против ретривнутых пассажей;
  faithfulness = доля подтверждённых утверждений.
- **Citation precision/recall**, **coverage** (совпадение ключевых пунктов),
  **self-confidence** (заявленная судьёй, 0-1).

JSON-выход ограничен guided-декодингом (lm-format-enforcer) с лимитами длины
полей, что даёт **0 ошибок парсинга** по всем 8640 judge-записям. Выход:
`outputs/judge/{judge_a,judge_b}/<track>/<model>/<cell>.jsonl`.

**Результаты (агрегат, `outputs/judge/aggregate_stats.json`):**

(Это чистые значения ПОСЛЕ пере-судейства; см. раздел 4 про коллизию QASPER/RAG,
которая была исправлена. Авторитетные числа надёжности/калибровки - из
`analyze_h3_reliability.py`; `aggregate_stats.json` пересчитан через
`judge_aggregate.py` после пере-судейства - judge_b дозужен на 36 hybrid RAG-ячейках,
которые он пропустил, и оба судьи теперь покрывают идентичные n = 4320 пар.)

- **Krippendorff alpha (judge_a vs judge_b) = 0.664**, 95% CI [0.646, 0.681] по
  n = 4320 совместно оценённых ответов (ordinal) - **substantial** согласие.
- **alpha(a,b,c) = 0.664** (равно парному, т.к. judge_c не запускался).
- **Per-judge ECE** (MCQ/short-answer субсет, B=10): judge_a 0.103, judge_b
  0.231 - оба > 0.05 (умеренная переуверенность).
- Perturbation Wilcoxon - **проведён** (см. H3, раздел 3): class 1 delta = -0.04
  (Cliff's d +0.02, пренебрежимо), class 2 delta = -0.33 (p = 4.6e-19,
  Cliff's d +0.15).

Per-judge: judge_a строже, judge_b мягче. Рубрика по **доменам** (Track A =
SciKnowEval, 4 нативных домена): Chemistry > Physics > Materials > Biology.
Важно: низко-рубричная группа **«CS» - это QASPER (Track B / NLP-статьи)**,
отдельный датасет, **не** домен SciKnowEval (у SciKnowEval только
Biology/Chemistry/Physics/Materials; проверено по карточке HF). Формулировки,
перечислявшие Computer Science среди доменов SciKnowEval, путали Track B с A.

**Понимание.** Судьи согласуются существенно (alpha = 0.66), рубрика - надёжный
сигнал качества. Faithfulness низкий повсюду (citation-runaway L4 + строгий NLI).
QASPER (Track B, open-ended NLP-QA) - самый трудный набор (минимум рубрики).
Калибровка умеренная (ECE обоих судей > 0.05).

### Фаза I - Статистика (таблицы Главы 5)

**Как.** `scripts/run_statistics.py` читает по-ячеечные сводки Exact Match

## 3. Гипотезы (диплом, RQ1-RQ3)

Это формальные гипотезы диплома. Раздел 3S собирает дополнительные анализы на
основе Exact Match - они отвечают на смежные, но иные вопросы и сохранены как
robustness/exploratory.

### H1 (RQ1) - Domain-aware рубрика vs лексические метрики

**Формулировка.** На unambiguous-gold closed-book субсете рубрика-судья
согласуется с правильностью лучше лексических метрик (ROUGE-L, BLEU-4); на
open-ended субсете ранг стратегий по рубрике отличается от ранга по лексическим
метрикам. Скрипт: `analyze_h1_metric_alignment.py`.

**Метод.** Point-biserial r(метрика, бинарная правильность) на unambiguous
субсете (MCQ + true/false, n = 384), сравнение rubric против трёх лексических
метрик {ROUGE-L, BLEU-4, exact-match} через Williams-тест для зависимых
overlapping-корреляций (тест семейства Steiger; Bonferroni alpha = 0.05/3 =
0.017); Kendall tau между рангами стратегий на open-ended субсете (n = 96).
Рубрика = среднее judge_a/b. Примечание: метка правоты (y_gold) - type-aware
exact match (`compute_exact_match`); EM-*конкурент* - сырое строковое равенство
answer-vs-gold (другая операционализация), поэтому сравнение rubric-vs-EM
полу-циркулярно, и основное свидетельство - rubric vs ROUGE-L/BLEU-4.

**Результат.**

| метрика | r_pb(метрика, correct) | Williams vs rubric |
|---|---|---|
| **rubric** | **0.674** | - |
| ROUGE-L | 0.533 | t = 3.97, p = 8.6e-5 (rubric выше) |
| BLEU-4 | 0.387 | t = 7.45, p = 6.4e-13 (rubric выше) |
| exact-match | 0.307 | t = 9.10, p < 1e-15 (rubric выше) |

Все три сравнения Bonferroni-значимы (alpha = 0.017). Ранг стратегий
(open-ended): rubric = RAS > CTL > DA > SC; vs ROUGE-L Kendall tau = 0.667;
vs BLEU-4 tau = 0.333; vs exact-match tau = 0.333.

**Понимание.** **H1 подтверждается.** Рубрика коррелирует с правильностью
значимо сильнее каждой лексической метрики (Williams, все три Bonferroni-значимы) -
domain-aware рубрика ловит качество ответа лучше поверхностного совпадения.
Ранги стратегий по рубрике и по лексике расходятся (tau < 1), т.е. выбор метрики
меняет выводы о стратегиях. Оговорка: предсказание «макс. расхождение у RAS» не
подтвердилось - RAS топ по всем метрикам; расхождение в середине ранга.

### H2 (RQ2) - Closed-book компетентность и устойчивость RAG

**Формулировка.** Closed-book научная компетентность предсказывает качество
ответа под RAG, а качество падает с ростом шума 0%->60%. Скрипт:
`analyze_h2_competence_robustness.py`.

**Метод.** Question-level mixed-effects на судейском RAG-субсете (n = 2880):
`rubric ~ closed_book_correct + noise_level + C(strategy) + (1 | model)`, где
`closed_book_correct` (EM-правильность той же model/strategy/question в
closed-book) - ключевой предиктор; OLS с моделью как fixed-effect - как
robustness-check. Модель-уровень (описательно, n = 6): thesis robustness slope =
нормализованная просадка (eq. 12, (rubric@0%-rubric@60%)/rubric@0% на hybrid) и
Spearman между closed-book рубрикой и просадкой, с 10k bootstrap CI.

**Результат.**

- **closed_book_correct: coef = +0.85, p = 5.5e-74** (mixed) / +0.85,
  p = 5.4e-70 (OLS, R^2 = 0.20, n = 2880). Правильный closed-book ответ
  предсказывает ~+0.85 к RAG-рубрике. [Random-intercept сингулярен - дисперсия
  поглощена closed_book_correct - OLS даёт чистую оценку; обе совпали.]
- **noise_level: coef = -0.09, p = 0.37 (НЕ значимо)** - при контроле
  компетентности и стратегии шум ретривала не является значимым пулинговым
  предиктором рубрики. (EM-модель тоже не показывает реального штрафа за шум;
  прежняя цифра «-0.26, значимо» была артефактом неполного покрытия judge_b на
  hybrid 0%/60% и устранена back-fill'ом - см. раздел 4.)
- Нормализованная просадка (eq. 12, 0%->60% на hybrid): **gemma +0.158**
  (максимум без конфаунда), llama +0.089, nemo +0.055, deepseek +0.032,
  qwen +0.018, **sciphi -0.543** (рубрика *растёт* с шумом - format-collapse
  конфаунд, L3). Пять из шести моделей дают положительную (деградирующую)
  просадку, но она мала и незначима в пулинговой модели.
- Spearman(closed-book рубрика, просадка) = **-0.14, p = 0.79**, 95% bootstrap
  CI [-1.0, 1.0] (n = 6, описательно - CI неинформативен при таком n).

**Понимание.** **H2 подтверждается частично.** Главная ветвь держится прочно:
closed-book компетентность - высоко значимый предиктор качества RAG (+0.85,
p ~ 1e-70). Вторичная ветвь - что шум ретривала снижает рубрику - присутствует
направленно (5 из 6 моделей дают положительную просадку), но **статистически
незначима** в пулинговой модели (-0.09, p = 0.37) при контроле компетентности и
стратегии. На модель-уровне связь компетентность-устойчивость лишь описательна
(n = 6, н.з., CI неинформативен); SciPhi - выброс (рубрика растёт с шумом,
format-collapse, L3). Ярлык «competent but context-fragile» ложится на
llama-3.2-3b (компетентность выше медианы, максимальная просадка без конфаунда),
но статистически не установлен при n = 6.

### H3 - Надёжны и калиброваны ли LLM-судьи?

**Формулировка.** Автоматическая панель судей даёт надёжные, калиброванные оценки
качества.

**Метод.** Krippendorff alpha (ordinal) между судьями по каждому совместно
оценённому ответу; Expected Calibration Error на MCQ-субсете (self-confidence vs
корректность, 10 бинов); парный Wilcoxon на аудите из 200 вопросов (class 1
surface vs class 2 semantic, обе судьи).

**Результат.**

- Межоценочная надёжность **alpha = 0.664**, 95% bootstrap CI [0.646, 0.681]
  (n = 4320) - в предсказанном диапазоне 0.40-0.80 и ниже near-perfect (< 0.85).
  H3(b) требует панель из трёх судей; трёхсторонний alpha(a,b,c) ждёт judge_c.
- **Per-judge ECE** (B=10, MCQ/short-answer): judge_a **0.103** (n=2688),
  judge_b **0.231** (n=2688) - оба > 0.05, т.е. H3(c) выполнен для каждого судьи.
- **Perturbation Wilcoxon + Cliff's delta** (аудит 200 вопросов, 6 моделей, da,
  обе судьи, ~1200 пар/класс). Class 2 прогнан в **двух** операционализациях -
  на уровне ВОПРОСА (negation + ре-инференс) и черновичной §3.6.4 на уровне
  ОТВЕТА (сохранённый ответ padding/truncation и пере-судейство того же вопроса,
  изолируя судью):
  - class 1 (surface: опечатки/пробелы в вопросе): рубрика 3.54 -> 3.50,
    delta = **-0.04**, p = 0.048, Cliff's delta = +0.023 (пренебрежимо);
  - class 2 (semantic, negation вопроса): рубрика 3.54 -> 3.22,
    delta = **-0.33**, p = 4.6e-19, Cliff's delta = +0.146 (small);
  - class 2 (semantic, **truncation ответа**, §3.6.4): рубрика 3.54 -> 3.36,
    delta = **-0.18**, p = 1.7e-15;
  - class 2 (semantic, **padding ответа**, §3.6.4): рубрика 3.54 -> 3.48,
    delta = **-0.06**, p = 0.024.

**Понимание.** **H3 подтверждается.** Два независимых open-weight судьи
согласуются существенно (alpha = 0.66, в полосе 0.40-0.80). Оба судьи умеренно
переуверены (ECE > 0.05). Аудит возмущений даёт нужную картину: каждое
Class-2 семантическое возмущение значимо роняет рубрику, а Class-1 поверхностное
пренебрежимо (delta = -0.04; пересекает p < 0.05 лишь из-за большой выборки).
Главное: **обе** операционализации Class 2 согласны - negation вопроса (-0.33) и
черновичная §3.6.4 на уровне ответа: truncation контента (-0.18, p = 1.7e-15) и
padding наполнителем (-0.06, p = 0.024) - все значимо падают, причём удаление
контента бьёт сильнее разбавления. Панель **устойчива к поверхностному шуму и
чувствительна к смыслу**, и вывод держится независимо от способа возмущения.

### 3R - RAG-метрики использования контекста: ACU и Denoise Rate (eq. 9 / 11)

**Метод.** Две определённые в черновике RAG-метрики (Sec 3.7.2), которых основной
пайплайн не выдавал, посчитаны постфактум через `compute_acu_dr.py`:
- **ACU (Answer-Context Utility)** = доля *релевантных* (real) извлечённых
  пассажей, чьё содержание отражено в ответе;
- **Denoise Rate (DR)** = 1 - доля *шумовых* пассажей, отражённых в ответе (при
  noise 0% не определена).
«Отражён» = NLI-entailment ответа пассажем (premise = пассаж, hypothesis = ответ,
entailment >= 0.5), та же модель DeBERTa-v3, что и для faithfulness. Hybrid-ретривер,
первые 20 отсуженных записей на ячейку (96 ячеек). Текст пассажей резолвится на
100% (376/376): реальные - из `corpus/all_chunks.jsonl`, синтетические шумовые
(injection `inj_*`, contradictory `con_*`) - из пулов `corpus/noise` по `noise_id`.

**Результат.**

| noise | 0% | 20% | 40% | 60% |
|---|---|---|---|---|
| **ACU** | 0.036 | 0.036 | 0.035 | 0.026 |
| **DR**  | -    | 0.978 | 0.936 | 0.927 |

- По стратегиям - ACU: ctl 0.038, da 0.034, ras 0.034, sc 0.027; DR: ctl 0.951,
  da 0.939, ras 0.948, sc 0.950.
- DR по моделям: qwen 0.957, nemo 0.957, gemma 0.954, llama 0.949, sciphi 0.933,
  deepseek 0.932.

**Понимание.** **Denoise Rate высокий (~0.93-0.98)**: модели почти не пропускают
дистрактор/противоречие/инъекцию в ответ, и DR лишь слегка падает с ростом шума
(0.98 -> 0.93 от 20% к 60%) - набор моделей устойчив к мусорному контексту.
**ACU очень низкий (~0.03)**: по строгому NLI-критерию ответы отражают почти
ничего даже из *релевантных* пассажей - это согласуется с низким faithfulness
(L4 citation-runaway + строгий порог entailment), а не с реальным неиспользованием
контекста; при 60% шума ACU падает ещё (релевантное вытесняется). Вместе метрики
говорят: модели хорошо *игнорируют* шум, но NLI-метрика фиксирует мало явного
*заземления* в извлечённом тексте - тот же сигнал, что и faithfulness. (ACU/DR -
описательные RAG-метрики, на H1/H2/H3 не влияют.)

### 3S - Дополнительные анализы на основе точности

Используют Exact Match (не рубрику) и отвечают на смежные, но иные вопросы.
Сохранены как exploratory/robustness (`run_statistics.py`).

- **Масштабирование с размером.** По (model, strategy) прирост RAG = RAG EM -
  closed-book EM. Pearson r(size, прирост) = 0.17 (p = 0.74), Kendall tau = 0.14
  (p = 0.70), Steiger z = -0.59 (p = 0.56); corr(size, closed-book) = 0.62 vs
  corr(size, RAG) = 0.35; все 6 дельт отрицательны; ни одна не проходит FDR.
  Чтение: RAG равномерно снижает MCQ-точность, и дефицит не масштабируется с
  размером (ср. механизм доменного mismatch в Фазе F).
- **Noise-модель на точности.** Mixed model `EM ~ noise_level + C(strategy) +
  C(retriever) + (1 | model)` (n = 144): noise_level +0.061 (p = 0.002,
  FDR-знач.), SC +0.060 (p = 3.5e-9), DA +0.025 (p = 0.013), ретривер н.з.
  Положительный знак шума - **артефакт SciPhi**: без SciPhi (n = 120)
  noise_level -0.006 (p = 0.69, н.з.), эффекты стратегий сохраняются (SC +0.066,
  p = 1.5e-20). Чтение: для здоровых моделей шум не влияет на *точность* MCQ;
  доминирует стратегия (SC > DA > RAS); ретривер н.з. (Контраст с рубричной
  Track-B QASPER, где шум *описательно* снижает open-ended качество, 2.23 -> 2.05
  - EM-точность маскирует то, что ловит рубрика там. В рубричной модели H2
  (Track A) шум тоже не является значимым пулинговым предиктором, так что разрыв
  рубрика/EM ярче всего на open-ended QASPER, а не на SciKnowEval MCQ.)
- **Разложение RAG-просадки** (EM vs EM_parsed) и **таблица Track-B QASPER**:
  см. Фаза F и Фаза G.

## 5. Ограничения (указать в дипломе)

- **L1 - Парсинг.** Парсинг успешен на 87.3% из 432 432 RAG-генераций; из 12.7%
  провалов 8.2 п.п. восстановлены fallback'ом по полю ответа, остаётся ~1.5%
  реальной потери. Сводный re-parse не делался: ~95% провалов - реальное
  не-отвечание модели, а перепарсинг после судейства рассинхронизировал бы
  посчитанные оценки судей. На выводы не влияет.
- **L2 - RAG ниже closed-book / знак шума.** RAG-точность равномерно ниже
  closed-book на MCQ без масштабирования с размером (H1). Это сохраняется на
  чистых ответах (delta EM_parsed -0.019…-0.047 у здоровых моделей), что
  подтверждает настоящий эффект дистракции знания, а не артефакт парсинга;
  меньший дополнительный штраф за формат (больше непарсящихся RAG-ответов)
  раздувает сырой EM-разрыв. Положительный коэффициент шума в полной H2 -
  артефакт format collapse у SciPhi и того, что шум сосредоточен на hybrid;
  исключение SciPhi его убирает. Это **не** значит, что шум улучшает ответы.
- **L3 - Format collapse у SciPhi.** SciPhi-Mistral демонстрирует RAG format
  collapse (Cliff's delta = 1.0 против всех; parse rate растёт с шумом),
  репортится как задокументированный выброс. Корень - отсутствовавший
  chat-шаблон `mistral_instruct` (исправлено и перегенерировано до финальных
  прогонов).
- **L4 - Citation runaway.** ~27% генераций упираются в лимит 1024 токена с
  вырожденным citation-спамом (`[2][3]...[220]`). На извлечённые ответы/точность
  не влияет, но занижает judge citation/faithfulness.
- **L5 - Калибровка/возмущения судей.** Надёжность solid (alpha = 0.66,
  CI [0.65, 0.68]); per-judge ECE 0.10/0.23 (оба > 0.05). Аудит возмущений
  **проведён** (200 вопросов, 6 моделей, обе судьи) в **обеих**
  операционализациях Class 2: вариант на уровне ВОПРОСА (negation + ре-инференс,
  delta = -0.33, p = 4.6e-19) **и** черновичный §3.6.4 на уровне ОТВЕТА с
  пере-судейством сохранённого ответа - truncation (delta = -0.18, p = 1.7e-15) и
  padding (delta = -0.06, p = 0.024). Все Class-2 варианты значимо падают, Class 1
  пренебрежим (-0.04), так что вывод «устойчив к поверхности / чувствителен к
  смыслу» держится при обоих протоколах (вариант на уровне ответа дополнительно
  изолирует судью от вариативности модели). Остаточный пробел: третий
  (проприетарный) судья не запускался, поэтому трёхсторонний alpha равен парному.
- **L6 - QASPER.** Track B - приложение; 10% вопросов unanswerable; Exact Match
  не информативен для open-ended, поэтому качество оценивается рубрикой. Спаны
  QASPER `highlighted_evidence` переносятся в сплит (`split_qasper.py`), но **не**
  используются для ground-truth валидации grounding/citation - Track B это
  рубрика + NLI transfer-проверка, поэтому довод «спаны компенсируют отсутствие
  человеческих меток» к прогнанным результатам не применим. Метрика
  span-grounding реализована как future-work инструмент
  (`qasper_evidence_grounding.py`: NLI ответ-vs-золотые-спаны), но не может быть
  посчитана представительно на оценённом наборе: реально прогнанный Track B
  сэмпл (600 вопросов) не содержит поля evidence, а evidence-сэмпл пересекается с
  ним лишь на 66/582 вопросов - поэтому grounding по спанам остаётся future work
  до evidence-выровненного пере-сэмпла.
- **L7 - Пересечение генератора контр-пассажей.** Контр-пассажи (`con_*`)
  сгенерены Qwen2.5-7B-Instruct - одной из шести экзаменуемых моделей. Это
  потенциальный confound именно для *contradictory*-условия (модель может быть
  по-разному устойчива к противоречиям в собственном стиле); irrelevant и
  injection не затронуты, а оба рубричных судьи (Llama-3.1-8B, Mistral-7B-v0.3) и
  шаг claim-decomposition дизъюнктны с экзаменуемыми. Ручной ревью 50 контр-
  пассажей принял **90% (45/50)** (`build_noise contradictory-review`).
- **L8 - Неисполненные элементы дизайна (threats to validity).** (a) Детекция
  контаминации (canary / n-gram / Fisher) **не** запускалась - артефактов нет,
  поэтому утечка адресована только parse-loss диагностикой (L1), а не сканом, и по
  утечке вопросы не исключались; selective escalation к третьему судье тоже не
  запускался (judge_c отсутствует). (b) Retrieval Recall@10 на финальном
  оценённом наборе (`main_test_sampled.json`, n = 3003) - прокси по присутствию
  ответа (референс-ответ в топ-10, не человеческая разметка релевантности): strict
  20.4% bm25 / 21.1% dense / 21.2% hybrid; relaxed (семантика) 89.6% / 71.3% /
  100.0%. Strict низкий, т.к. точная строка ответа редко встречается в пассажах
  дословно; высокий relaxed hybrid означает, что семантически релевантный контекст
  почти всегда извлекается.

## 8. Краткое резюме результатов (под аннотацию)

Мы оценили шесть open-weight LLM (3-12B) на научном QA (SciKnowEval; transfer-
трек QASPER) в closed-book и retrieval-augmented режимах, по четырём стратегиям
промптинга, трём ретриверам и четырём уровням шума (0-60%), с панелью
LLM-судей по domain-aware рубрике. **(H1)** Рубрика согласуется с эталонной
правильностью значимо лучше лексических метрик (point-biserial r = 0.67 vs
ROUGE-L 0.53, BLEU-4 0.39; Williams p < 1e-4), а ранги стратегий по рубрике
расходятся с лексическими (Kendall tau 0.33-0.67). **(H2)** Closed-book
компетентность сильно предсказывает качество ответа под RAG (mixed-effects/OLS
коэф. +0.85, p < 1e-69); шум ретривала даёт лишь направленный незначимый штраф
по рубрике в пулинговой модели (-0.09, p = 0.37), а связь
компетентность-хрупкость на модель-уровне лишь намекается (Spearman -0.14, н.з.
при n = 6). **(H3)** Панель судей надёжна (Krippendorff alpha = 0.66, в
диапазоне 0.40-0.80), умеренно калибрована (per-judge ECE 0.10/0.23), устойчива
к поверхностным возмущениям (rubric delta -0.04) и чувствительна к семантическим
(delta -0.33, p = 4.6e-19). Дополнительные анализы на точности показывают, что
RAG уступает closed-book на MCQ без масштабирования с размером - из-за
неравномерной кросс-доменной релевантности ретривала (domain-match 8-85%) - а
стратегия промптинга (SC > DA > RAS) - доминирующий управляемый фактор. Все
инференциальные выводы скорректированы по FDR/Bonferroni и подкреплены
автоматическим аудитом целостности по 533 304 inference-записям.
